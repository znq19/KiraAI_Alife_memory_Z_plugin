# 面板「编辑 / 保存 / 删除」全链修复（v2.21.3）

> 起因：用户实测 **「KiraOS 迁移过来的记忆删不掉」** ✗ —— 面板点了「确认删除」没反应 ✓
> 方法：我自己逐行审 + 真 handler 矩阵 + 反向验证（**不派子代理** ✓）

## 一、根因（P0：「跳过版本比对」的契约没被兑现）

```
前端「确认删除」= saveEdit({deleted:true}) ⇒ POST /edit
  ⇒ main.edit_skip_revision 判「纯删除」/「force」⇒ skip=True
  ⇒ 调用方把 revision 置为 None   ← 这是**契约**（表示"不比对"✓）
  ⇒ store.edit 里写的是：if not old or old["revision"] != revision: raise Conflict
  ⇒ **None 永远不等于任何版本号** ⇒ 必然 Conflict ⇒ HTTP 409 ✗
```

**受害面**（全部真跑复现 ✗）：

| 入口 | 走跳过契约？ | 结果 |
|---|---|---|
| 面板「确认删除」 | ✓（纯删除） | 必然 409 ✗ |
| 「以我的版本覆盖」 | ✓（force） | 必然 409 ✗ |
| AI 工具 `correct()`（默认不带版本号） | ✓ | 必然 409 ✗ |
| 体检页「删除 / 重要度 ±1」 | ✓ | 必然 409 ✗ |
| 回收站还原 | ✓ | 必然 409 ✗ |
| 面板「保存修改」（带**真实**版本号） | ✗ | 正常 ✓ |

**修**：`storage.py` → `if revision is not None and old["revision"] != revision:`
（与同仓库 `names` 路径 storage.py:1184 的既有写法对齐 ✓）

## 四、KiraOS 迁移记录形态（实测）

```
id=legacy-<sha256> ✓ level=0（不会 NULL ✓）✓ summary==content ✓
content = 六键 JSON 信封 ✓ permanent=0 ✓ revision=1 ✓
```
⇒ 与普通记录走**同一代码路径**，修复后**可正常编辑 / 保存 / 删除** ✓

⚠️ 删一条迁移记录会经 `_orphan_facts` **连带软删它派生的事实** ✓
   —— 面板确认框文案**已明确告知**（「仅以它为证据的事实也会停用，已生成的父摘要要保留」✓）
